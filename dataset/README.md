# Синтетический датасет технической документации

Набор построен по обязательному шаблону и трем согласованным источникам ошибок. Все данные, идентификаторы и ссылки синтетические.

## Состав

- `clean/` — 10 эталонных документов;
- `corrupted/` — 50 измененных документов и ground truth;
- `train/`, `val/`, `test/` — относительные symlink-ссылки на те же файлы, без копий;
- `error_catalog.json` — 120 фактически используемых вариантов, покрывающих все `D01–D08`, `T01`, `U01–U19`;
- `manifest.json` — сводное распределение и счетчики;
- генератор и валидатор находятся непосредственно в `src/`.

Каждый эталон порождает ровно пять кейсов. Суммарная нагрузка на эталон — 62 или 63 ошибки. Число ошибок распределено максимально равномерно: `0` и `25` встречаются по одному разу, каждое значение `1–24` — дважды. Всего внесено 625 ошибок; все 50 комбинаций уникальны.

Сплит не допускает утечки исходных clean-документов: `clean_01–06` и `case_001–030` входят в train, `clean_07–08` и `case_031–040` — в val, `clean_09–10` и `case_041–050` — в test.

## Формат metadata

В `corrupted/case_XXX.json` находятся только четыре поля: `document_id`, `source_clean_document`, `error_count` и массив `errors`.

Одна ошибка содержит:

- `error_type_id`, `source_type`, `difficulty`;
- `evidence_quote` — цитата, встречающаяся в Markdown ровно один раз;
- `title`, `problem`.

Сводные счетчики не дублируются в каждом JSON: они однозначно вычисляются из `errors`.
Одна логическая ошибка может быть внесена несколькими согласованными изменениями в разных разделах документа.

## Проверка и воспроизведение

Из корня репозитория:

```bash
uv run dataset-generate
uv run python -m unittest discover -s tests -v
```

Генератор детерминирован seed `20260903`. Валидатор проверяет структуру эталонов, согласованность mapping/example/DDL, 50 пар файлов, уникальность evidence, минимальную схему metadata, покрытие всех 28 классов, равномерность 0–25 и использование каждого эталона ровно пять раз.
