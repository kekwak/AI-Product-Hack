# Синтетический датасет технической документации

Набор построен по обязательному шаблону и трем согласованным источникам ошибок. Все данные, идентификаторы и ссылки синтетические.

## Состав

- `clean/` — 10 содержательно разных эталонных документов без известных ошибок типов 1–3;
- `corrupted/` — 50 измененных документов и 50 одноименных JSON-файлов с ground truth;
- `error_catalog.json` — 35 фактически используемых мутаций, покрывающих все `D01–D08`, `T01`, `U01–U19`;
- `manifest.json` — сводное распределение и счетчики;
- генератор и валидатор находятся непосредственно в `src/`.

Каждый эталон порождает ровно пять кейсов. Суммарная нагрузка на эталон — 62 или 63 ошибки. Число ошибок распределено максимально равномерно: `0` и `25` встречаются по одному разу, каждое значение `1–24` — дважды. Всего внесено 625 ошибок; все 50 комбинаций уникальны.

## Формат metadata

В `corrupted/case_XXX.json` верхний уровень содержит источник, seed и версию генератора, SHA-256 обоих документов, ожидаемое число ошибок и счетчики по источнику, сложности и классу. Поле `errors` — `list[dict]`.

Одна ошибка содержит:

- `instance_id`, `mutation_id`, `error_type_id`, `source_type`;
- `difficulty`, `priority`, `roles`;
- `evidence_quote` и `evidence_relation`; цитата встречается в Markdown ровно один раз;
- `title`, `problem`, `clarification_needed`;
- `affected_sections`, `injected_change`.

Рекомендация требует уточнения и не выполняет автоисправление.

## Проверка и воспроизведение

Из корня репозитория:

```bash
uv run dataset-validate
uv run dataset-generate
```

Генератор детерминирован seed `20260903`. Валидатор проверяет структуру эталонов, согласованность mapping/example/DDL, 50 пар файлов, хеши, уникальность evidence, схему metadata, покрытие всех 28 классов, равномерность 0–25 и использование каждого эталона ровно пять раз.
